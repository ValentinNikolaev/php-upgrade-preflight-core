# PHP Upgrade Preflight v0.3.4

Released 2026-10-07.

## Purpose and compatibility

v0.3.4 completes the bounded Laravel coverage review before the v0.4 foundation and Symfony adapter work. It retains report schema `0.8`, the PHP `^8.0` analyzer floor, `0.3.x-dev` branch aliases, `^0.3` internal constraints and the three-package release set. Existing public calls, CLI/Artisan flags, exit policy and required adapter interfaces remain compatible. Optional library-level source-scan controls are additive; this is not a claim that every internal class is unchanged.

The supported matrix remains Laravel 7→8, retained direct 7→9 guidance, and adjacent ascending hops through 12→13. Illuminate-only, mixed framework/component and same-major requests retain direct Composer analysis but do not gain staged solving or new framework-hop support. Schema consumers continue to dispatch on `metadata.schema_version`, not the tool-version string. No schema migration is needed from an earlier v0.3 patch.

## Laravel corrections

- Preserve supported alternative PHPUnit and Collision branches instead of requiring an unnecessary major upgrade. Correct Guzzle, Pusher and Laravel UI ranges using reviewed framework manifests and published package evidence.
- Account for Socialite, Nexmo→Vonage, SwiftMailer Postmark→Symfony Postmark and `spatie/once` removal guidance within existing catalog hops.
- Detect exact removed `elixir` calls, Illuminate serializable-closure classes, `MocksApplicationServices` and `HasVersion7Uuids`, with alias/import, negative and hop-attribution coverage. Unresolved namespaced function fallbacks remain manual review. Queue-dispatch guidance no longer matches unrelated facades named Bus.
- Treat Laravel 13 `VerifyCsrfToken` and `ValidateCsrfToken` as retained deprecated aliases: direct/inherited references receive medium-severity migration review, not a removed-class blocker. Retaining the Laravel 10 skeleton on Laravel 11 remains supported.

The [coverage ledgers](../laravel-coverage/README.md) account for all 299 reviewed guide headings at pinned upstream commits. Each item is implemented, corrected, manual review, not applicable or contract-dependent; this accounting is not exhaustive ecosystem or runtime support.

The [application evaluation](../laravel-coverage/application-evaluation.md) compares the exact published v0.3.3 baseline with the corrected pre-release implementation on pinned Crater, BookStack and Lychee snapshots, plus two supplemental BookStack versions. Report changes include removing unsupported package warnings and adding the actual deprecated CSRF reference. All completed analyses preserved input bytes. Recorded Composer outcomes, access retries, cache/network timing and manual follow-up remain distinct from application-runtime testing; these applications were not upgraded or booted.

## Earlier merged changes included in this patch

The released payload also includes changes merged after v0.3.3 and before the Laravel completion PR:

- Optional adapter capability failures are contained as evidence-backed uncertainty across detection, default source paths, transitions and package classification.
- Source inspection has finite default caps: 10,000 files, 2 MiB per file, 64 MiB total input and 10,000 usages. Omitted inputs and bounded drift checks are visible as uncertainty. Optional library controls preserve existing call signatures.
- Staged blocker registration was simplified without changing insertion order or blocker lifecycles.
- Pinned GitHub Actions runtimes were refreshed. Documentation distinguishes enforced scan limits from advisory representative-corpus budgets and explains the conditions for cross-host fingerprint stability.

## Upgrade and user follow-up

Existing `^0.3` constraints select this patch:

```bash
composer update php-upgrade-preflight/core php-upgrade-preflight/cli php-upgrade-preflight/laravel --with-all-dependencies
```

For a separate tools installation:

```bash
composer require php-upgrade-preflight/cli:^0.3 php-upgrade-preflight/laravel:^0.3
```

Rerun analysis, review changed findings and evaluate direct resolution, framework guidance and staged resolution independently. Apply upgrade work in the application's own branch, then run its tests, database/runtime checks and deployment review. For excluded staged cases, retain all intended direct targets; do not discard a conflicting component merely to obtain a staged verdict.

Dynamic/container/configuration behavior, database state, custom contracts, migration data and unreviewed ecosystem versions still require manual verification. The analyzer does not edit, boot or prove production compatibility of the target.
